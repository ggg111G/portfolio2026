AI-Driven Design System Workflow 2026 Dynamic Yield / Mastercard
The Problem

1. Prototyping. Figma prototyping hits a ceiling — especially when designing an AI-generated content based product. No real data, hard to reproduce actual agent behavior. Hard to test ideas before they're built.

2. Design system drift. The system changes fast, with several dev teams building against it in parallel. Keeping it updated and reachable for every dev felt like a constant struggle.

3. Dev velocity. Devs are using LLMs to generate UI directly. They need the quickest path from the Figma design system to generated UI.

My Role

As the team's Claude Code ambassador, I have early access and build tools myself — directly in a code repository, not just Figma. I set up and maintain the design repo the dev team and other designers now work from.

What I Built

1. GitHub Repository — A single place for the design system documentation, prototypes, and the skills below. It lives alongside the product repository, which gives me access to real product data and lets prototypes run against the real agents skills. The dev team and other designers work from it directly.

2. Documentation Skill — Generates component docs from the Figma design system, written for both team members and AI agents to read. Organizes components in a consistent pattern, so the design system stays uniform even with multiple designers contributing. The base the other two skills build on.

3. Sync Skill — Keeps the design system and repository aligned as components change, so devs generating UI with LLMs are always pulling current components.

4. Prototype & Spec Skill — Turns the design system into working, interactive prototypes and dev specs, simulating real agent content. Replaces static Figma flows with something devs and stakeholders can actually interact with.

Impact
  • Testing ideas that were previously hard to explore in Figma — closer to real interactions, real logic, real LLM content
  • Sharing working prototypes with CS and customers, not just static flows
  • Documenting new features faster through generated spec files
  • Fewer dev errors, since specs come from the design system rather than manual translation
Adoption

The repository became a shared source for the team. Devs reference and build on it directly.
